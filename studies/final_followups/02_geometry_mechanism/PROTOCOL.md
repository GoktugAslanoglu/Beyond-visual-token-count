# Controlled rendered text-block scale — prospective protocol v1
32 fresh five-record identifier cases using seed 202609230102, 8192 +/-32 reference tokens, four distractors. Fixed 2 lengths x 2 alphabets x 2 entropy patterns x 4 instances, 32 cases. Target positions rotate early/middle/late by index (11/11/10); no position inference or selection. Reuse validated held-out template and source construction. No old development/evaluation case reused.
Three fixed scales 0.55, 0.75, 1.00 x 32 cases x three readers = 288 calls.

## Intervention
Compute L3_fullwidth_wordwrap source plan once per case using the validated font, line breaks, pagination and page content. Rasterize once at the planned base square resolution. For each scale, resize each complete base page to round(final_side * scale) square using Pillow LANCZOS, then center it on a white final_side square canvas. The unscaled source block and its whitespace are scaled together. Final saved sides are 1008 for each Qwen and 868 for GLM. No reflow, crop, changed font, source, question, or answer-conditioned transform. Pixel rounding is reported as realized scale.
The scale-1 condition equals direct validated L3 rendering at the same final side. Ink bounding boxes must stay strictly within the image at every scale; no source character/span may be omitted. Smaller rendered glyphs can lose perceptual distinctions; source-span preservation does not assert pixel-level recoverability of every character. The intervention is uniform rendered text-block scale/occupied area, not uniquely glyph height.
Pre-inference audit independently checks all 288 requests: source hash, exact ordered character spans/lines, page assignment, canvas, rerendered pixels, equal native vision count, nonvision IDs, total IDs and question across scales. Report ink bbox, width/height utilization, em, minimum ASCII bbox and minimum line bbox transformed heights. All input freezes precede all evaluation answers.

## Runtime and analysis
Same snapshots, BF16/SDPA, native processor and tokenizer pins, greedy 64-token cap and inference seed as Experiment 1. No tuning from accuracy. Source/protocol/input hashes and actual GPU environment are required.
Primary metric is existing canonical whitespace-normalized EM, without stripping arbitrary prose/Markdown. Primary test per reader: Cochran Q statistic with EXACT conditional within-case label permutation distribution (dynamic programming, no asymptotic chi-square approximation). Cases with zero or three successes carry no random permutation; one/two success cases have three equally likely arrangements. Holm over three reader tests.
Secondary comparisons: 1.00-.55, 1.00-.75, .75-.55, each exact two-sided McNemar plus gains/losses and paired bootstrap 95% intervals. Separate conservative Holm family across all nine secondary reader/pair tests. 50,000 paired case resamples, seed 202609230105. Report EM and CER for each scale. n=32 supports only this fixed diagnostic, not a universal law; intervals are pointwise. No monotonic law from a single omnibus test.
Positive conclusion: recoverability changes under this scale intervention holding source/wrapping/pagination/count/question fixed. Negative or uncertain result: this diagnostic does not explain the earlier layout-package effect; lack of significance is not proof scale has no effect.
